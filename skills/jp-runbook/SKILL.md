# 運用手順書（ランブック）を作る

疲れていても、初めての人でも、書いてあるとおりにやれば完了する粒度にする。危険な操作の前に確認を置く。

## 先に確認すること
- 作業の目的、頻度
- 実行する人の知識
- 使う環境・コマンド
- 失敗時の連絡先

## 手順
1. 目的と、実行するタイミングを書く。
2. 事前条件（権限、バックアップ、ツール）を一覧にする。
3. 手順を番号つきで、1操作ずつ書く。コマンドはそのままコピーできる形にする。
4. 各手順に、正常に終わったときの確認方法を書く。
5. 危険な操作（削除、本番反映）の前に、確認を置く。
6. 失敗したときの切り戻し手順と、連絡先を書く。
7. 最終更新日と担当者を書く。

## 出力形式
```
手順書：{作業名}
【目的】
【事前条件】
【手順】
【確認】
【失敗時の対処・連絡先】
```

## 例
入力：「月初に行う、サーバーのログの圧縮・保管。コマンドを実行して容量を確認する」
出力のポイント：
- 手順：1. ログのディレクトリへ移動。2. 圧縮コマンドを実行。3. 容量を確認（確認方法を併記）。
- 危険：削除前にバックアップの確認を置く。

## 注意
- 入力に無いコマンドを作らず、「要確認」とする。
- 本番環境での実行は、承認手順に従うよう添える。
