# 設計判断の記録（ADR）を書く

「何を選んだか」より「なぜ選んだか」「何を捨てたか」を残す。半年後の自分と新メンバーが読めるように書く。

## 先に確認すること
- 決めたこと、背景（課題）
- 検討した選択肢
- 決め手となった基準
- 影響とリスク

## 手順
1. タイトルに、決定の内容を書く（「データベースにPostgreSQLを採用する」）。
2. 背景として、解決したい課題と制約を書く。
3. 選択肢を挙げ、それぞれの利点と欠点を書く。
4. 決定と、決め手の理由を書く。
5. 影響（良い点、悪い点、今後の作業）を書く。
6. 状態（提案、承認、廃止）と日付を書く。

## 出力形式
```
# ADR-{番号}：{タイトル}
状態／日付
## 背景
## 選択肢
## 決定
## 理由
## 影響
```

## 例
入力：「DBは、PostgreSQLかMySQLか迷った。JSONの扱いと、チームの経験でPostgreSQLにした」
出力のポイント：
- 決定：PostgreSQLを採用。理由：JSONの扱い、チームの経験。
- 捨てた選択肢：MySQL（理由を記録）。

## 注意
- 入力に無い検討や数字を作らない。
- 後から決定が変わった場合は、書き換えず、新しいADRで置き換える。
