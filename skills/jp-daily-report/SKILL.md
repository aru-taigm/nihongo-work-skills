# 日報を作る

作業の羅列ではなく、「進んだこと」「困っていること」「明日やること」が伝わる日報にする。

## 先に確認すること
- 日付、報告先の相手
- 今日やったことの材料（メモ、チャット、チケット、コミットなど）
- 会社の日報の書式があるか（あればそれに合わせる）

## 手順
1. 作業を成果ごとにまとめる。「資料作成」ではなく「提案書の第2章まで完成」のように、状態が分かる書き方にする。
2. 時間の記録が入力にあるときだけ、所要時間を書く。
3. 「課題・相談」は、誰に何を判断してほしいかまで書く。
4. 「明日の予定」は優先順に並べる。

## 出力形式
```
日報（{日付}）{名前}

【今日の成果】
-

【課題・相談】
-（誰に／何を）

【明日の予定】
1.

【所感】（任意）
```

## 例
入力：「見積もり3件対応、A社の仕様確認でつまずいた、明日は仕様書をもらう」
出力：
```
【今日の成果】
- 見積書3件を作成・送付した

【課題・相談】
- A社の仕様が一部不明。先方担当に確認する必要がある（本日メールで依頼済みか、要確認）

【明日の予定】
1. A社から仕様書を受け取り、見積もりを更新する
```

## 注意
- 入力に無い成果や数字を作らない。
- 愚痴や他人への批判は載せず、事実と依頼に直す。
