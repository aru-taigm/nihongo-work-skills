# コードレビューのコメントを書く

人ではなくコードについて書く。理由と代案をセットにし、必須の修正と好みの提案を区別する。

## 先に確認すること
- 対象のコードと変更の目的
- 指摘したい点
- 相手の経験
- チームのレビューの規約

## 手順
1. 指摘を、必須（バグ、仕様違反）・推奨（可読性）・好み（nit）に分ける。
2. 「なぜ問題か」を一文で書く。
3. 可能なら、修正案のコードを添える。
4. 質問の形にして、相手の意図を聞くのも有効（「ここは〇〇の意図でしょうか」）。
5. 良い点も具体的に書く。
6. 全体のコメントでは、要約と、承認の条件（何が直れば承認か）を書く。

## 出力形式
```
[必須]／[推奨]／[nit]／[質問]
（コメント本文）
（修正案）
```

## 例
入力：「ループの中でDBに毎回問い合わせている。件数が増えると遅くなる」
出力のポイント：
- [推奨] ループの中で毎回問い合わせると、件数が増えたときに遅くなります。まとめて取得する方法はいかがでしょうか。
- 修正案のコードを添える。

## 注意
- 入力に無い仕様・要件を決めつけない。
- 人格を攻撃する表現を避ける。
