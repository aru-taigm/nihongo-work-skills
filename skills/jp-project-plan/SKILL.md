# プロジェクト計画書を作る

関係者が「何を、誰が、いつまでに、どこまでやるか」で合意できる計画書にする。範囲外のものも書く。

## 先に確認すること
- 目的と、成功の基準（何をもって完了とするか）
- 期限、予算、体制
- 前提条件と制約

## 手順
1. 目的、背景、ゴールを書く。ゴールは測れる形（数字、状態）にする。
2. 範囲を「やること」と「やらないこと」に分ける。
3. 成果物と、作業を分解したもの（WBS）を階層で書く。
4. スケジュールをフェーズごとのマイルストーンで示す。日付が不明なものは「要確認」とする。
5. 体制と役割分担（責任者、担当）を表にする。
6. リスクを3〜5個挙げ、発生時の対応を添える。
7. 連絡方法と会議体（定例の頻度）を決める。

## 出力形式
```
プロジェクト計画書：{名称}
1. 目的・背景
2. ゴールと成功基準
3. 範囲（やること／やらないこと）
4. 成果物とWBS
5. スケジュール（マイルストーン）
6. 体制と役割
7. リスクと対応
8. コミュニケーション計画
```

## 例
入力：「社内ポータルを3か月でリニューアル。担当は私と佐藤、デザインは外注。既存データの移行も含む」
出力のポイント：
- 範囲外：「スマートフォン向けアプリの開発」は含めない（入力に無いため確認事項として添える）。
- リスク：外注の納期遅れ。対応：中間レビューを2回設ける。

## 注意
- 入力に無い人名、金額、日付を作らない。
- 見積もりが必要な作業は、工数を決め打ちせず「要見積もり」とする。
