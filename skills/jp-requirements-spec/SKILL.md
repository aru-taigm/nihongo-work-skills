# 要件定義書を作る

「何を作るか」と「作らないこと」を明確にし、後から解釈が分かれる曖昧な表現を避ける。

## 先に確認すること
- 目的と背景
- 利用者と利用場面
- やりたいこと（機能の希望）
- 制約（予算、期間、環境）

## 手順
1. 目的と成功の基準を書く。
2. 利用者の種類と、それぞれがやりたいことを書く。
3. 機能要件を、「〜できる」の形で書き、優先度（必須、あれば良い）を付ける。
4. 非機能要件（性能、セキュリティ、可用性、使いやすさ）を書く。
5. 範囲外（今回やらないこと）を明記する。
6. 受け入れ条件（確認する観点）を、機能ごとに書く。
7. 未決事項を一覧にする。

## 出力形式
```
要件定義書：{名称}
1. 目的
2. 利用者
3. 機能要件（優先度）
4. 非機能要件
5. 範囲外
6. 受け入れ条件
7. 未決事項
```

## 例
入力：「社内の備品貸出管理アプリ。借りる人が申請し、管理者が承認する」
出力のポイント：
- 機能：申請の登録（必須）、承認・却下（必須）、貸出履歴の閲覧（必須）。
- 未決事項：返却期限、通知の方法。

## 注意
- 入力に無い要件を作らない。決まっていない点は未決事項にする。
- 個人情報・権限の扱いは、セキュリティ担当に確認するよう添える。
