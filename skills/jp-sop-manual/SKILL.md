# 業務手順書を作る

「分かっている人にしか分からない」手順を、初めての人が迷わず実行できる形に直す。

## 先に確認すること
- 手順書の読み手（新人、他部署、外部委託先）と、前提知識
- 作業の目的と、いつ行うか（毎日、月末、トラブル時）
- 使うツール、アカウント、権限
- 失敗したときの連絡先

## 手順
1. 冒頭に「目的」「実施タイミング」「所要時間」「必要なもの」を書く。
2. 手順を1ステップ1動作で番号を振る。「適宜」「よしなに」のような曖昧語を使わない。
3. 各ステップに、完了の確認方法（画面に何が出ればよいか）を添える。
4. 判断が必要な箇所は、条件分岐（もし〇〇なら△△）にして書く。
5. 画面操作は、メニュー名やボタン名を「」で書く。
6. よくある失敗と対処を、末尾にまとめる。
7. 版数と更新日、担当者を入れる。

## 出力形式
```
手順書：{タイトル}　版：　更新日：　担当：
■ 目的
■ 実施タイミング／所要時間
■ 事前準備
■ 手順
 1.（操作）
   → 確認：
■ よくある失敗と対処
■ 困ったときの連絡先
```

## 例
入力：「毎月末に請求書をPDFにして、共有フォルダに入れて、経理にチャットする」
出力のポイント：
- 手順1：「会計ソフトで『請求書』を開き、対象月を選択する。確認：一覧に当月の請求書が表示される」
- 保存先とファイル名のルールが無い場合は、質問する。

## 注意
- 入力に無い手順、権限、URLを作らない。足りない箇所は「要確認」と残す。
- 作成した手順は、実際に一度なぞって確認するよう添える。
