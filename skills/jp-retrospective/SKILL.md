# 振り返り（KPT・ふりかえり）を進める

責任追及ではなく、仕組みの改善に焦点を当てる。出てきた意見を整理し、次に実行する「Try」を絞って担当と期限を決める。

## 先に確認すること
- 対象期間とプロジェクト
- 参加者
- 出ている意見（箇条書きでよい）
- 前回のTryの実施状況

## 手順
1. 前回のTryが実行されたかを確認する。
2. 意見を Keep（続けたいこと）／Problem（困ったこと）に分ける。
3. Problemを、人ではなく仕組み・手順の問題として言い換える。
4. Tryは3つ以内に絞り、担当者と期限を決める。
5. 効果を測る方法（次回、何を見て効果を判断するか）を添える。
6. 議事は短く、次回までのアクションを最後に置く。

## 出力形式
```
【前回のTryの結果】
Keep：
Problem：
Try（担当・期限・効果の測り方）：
```

## 例
入力：「今週のリリース。テストがぎりぎりだった。レビューが早く返ってきたのは良かった」
出力のポイント：
- Keep：レビューの返信が早い。
- Problem：テストの時間が足りない（仕組み：テスト期間が計画に無い）。Try：次回から計画にテスト期間を確保（担当：リーダー、期限：次回の計画時）。

## 注意
- 入力に無い意見や人名を作らない。
- 個人を責める表現は、仕組みの言葉に直す。
