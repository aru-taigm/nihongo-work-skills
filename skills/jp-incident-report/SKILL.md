# 障害報告書・顛末書を書く

事実と推測を分け、時系列で何が起きたかを示す。責任の押し付け合いではなく、再発防止に使える記録にする。

## 先に確認すること
- 報告先（社内、顧客、取引先）と提出期限
- 発生日時、検知した方法、復旧した日時
- 影響範囲（人数、件数、金額、データ）
- 原因が確定しているか

## 手順
1. 冒頭に概要（何が、いつ、どの範囲に、今どうなっているか）を3行で書く。
2. 時系列を表にする。時刻は24時間表記で、分かる範囲だけ書く。
3. 原因は「直接の原因」と「根本の原因（なぜ防げなかったか）」に分ける。確定していなければ「調査中」とし、判明する時期を書く。
4. 影響は、数字と対象を具体的に書く。
5. 対応は「応急対応（済）」と「恒久対策（予定）」に分け、担当と期限を付ける。
6. 顧客向けの場合は、お詫びと問い合わせ先を入れる。個人名や内部の責任追及は書かない。

## 出力形式
```
障害報告書
発生日時：　復旧日時：　報告日：　報告者：

■ 概要
■ 時系列
| 時刻 | 出来事 |
|---|---|
■ 影響範囲
■ 原因（直接／根本）
■ 対応（応急／恒久）
■ 再発防止策
```

## 例
入力：「3/5 14:20 管理画面にログインできなくなった。原因は証明書の期限切れ。14:50 更新して復旧。期限の管理が個人任せだった」
出力のポイント：
- 直接の原因：証明書の期限切れ。根本の原因：期限の管理が個人に依存し、通知の仕組みが無かった。
- 再発防止：期限の30日前に通知する仕組みを導入（担当・期限は要記入）。

## 注意
- 入力に無い影響件数や原因を作らない。不明な箇所は「調査中」「要確認」と書く。
- 法的責任や補償に関わる記載は、送付前に上長や法務に確認するよう添える。
